1、命名空间

1.1 什么是命名空间？namespace一种资源。

Kubernetes 支持多个虚拟集群，它们底层依赖于同一个物理集群。 这些虚拟集群被称为命名空间。

命名空间namespace是k8s集群级别的资源，可以给不同的用户、租户、环境或项目创建对应的命名空间，例如，可以为test（测试环境）、devlopment（开发环境）、production（生产）环境分别创建各自的命名空间。

1.2 namespace应用场景

命名空间适用于存在很多跨多个团队或项目的用户的场景。（运维团队、开发团队、测试团队这些）

对于只有几到几十个用户的集群，根本不需要创建或考虑命名空间。

1.3 namespacs使用案例分享

[root@master1 ~]# kubectl create ns test # 创建新的命名空间

namespace/test created

[root@master1 ~]# kubectl get ns # 查看ns

NAME STATUS AGE

default Active 29d

kube-node-lease Active 29d

kube-public Active 29d

kube-system Active 29d

test Active 3s

1.4 namespacs资源限额

# 关键查询，编写yaml的指引词（resourcequote）

[root@master1 ~]# kubectl explain resourcequota

⭐最重要的参数

spec:

hard:

requests.cpu: “1” # ⭐requests字面理解为请求，你要请求多少

requests.memory: 1Gi

limits.cpu: “2” # ⭐limits（限制嘛，限制整个用多少G），也就是总量

limits.memory: 2Gi

例子：创建一个pod，设置请求和总额

[root@master1 pod_study]# cat ns_resourcequota.yaml

apiVersion: v1

kind: ResourceQuota

metadata:

name: mem-cpu-quota

namespace: test

spec:

hard:

requests.cpu: “1”

requests.memory: 1Gi

limits.cpu: “2”

limits.memory: 2Gi

#⭐查看命名空间配额的详细信息（这样就可以看到命名空间的资源使用情况）

[root@master1 pod_study]# kubectl get resourcequota -n test # -n 指定命名空间

NAME AGE REQUEST LIMIT

mem-cpu-quota 11m requests.cpu: 0/1, requests.memory: 0/1Gi limits.cpu: 0/2, limits.memory: 0/2G
