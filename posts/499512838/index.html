故障类——k8s节点故障并快速修复（二进制部署）

发表于2026-05-07|更新于2026-05-08|故障类
|总字数:1.2k|阅读时长:6分钟|浏览量:

二进制部署master节点故障恢复（多master节点）

[场景：]{.mark}master1 宕机 → 节点删除 → 修复后重新加入控制节点

阶段一：存活节点上的集群清理(Master2 执行)

前提：安全检查（确保 Master2 和 Master3 的 Etcd 状态为健康）

etcdctl –endpoints=https://192.168.40.180:2379,https://192.168.40.181:2379,https://192.168.40.182:2379 \

–cacert=/etc/etcd/ssl/ca.pem –cert=/etc/etcd/ssl/etcd.pem –key=/etc/etcd/ssl/etcd-key.pem \

endpoint health

→ 这里发现master1是失联的

步骤 1：正常节点移除故障 Etcd（master2 执行）

/usr/local/bin/etcdctl –write-out=table \

–cacert=/etc/etcd/ssl/ca.pem \

–cert=/etc/etcd/ssl/etcd.pem \

–key=/etc/etcd/ssl/etcd-key.pem \

–endpoints=https://192.168.40.181:2379,https://192.168.40.182:2379 \

member list

+——————+———+——-+—————————–+—————————–+————+

| ID | STATUS | NAME | PEER ADDRS | CLIENT ADDRS | IS LEARNER |

+——————+———+——-+—————————–+—————————–+————+

| 1203cdd3ad75e761 | started | etcd1 | https://192.168.40.180:2380 | https://192.168.40.180:2379 | false |

| 18e1ac83234cec44 | started | etcd3 | https://192.168.40.182:2380 | https://192.168.40.182:2379 | false |

| 213823ebf4891b65 | started | etcd2 | https://192.168.40.181:2380 | https://192.168.40.181:2379 | false |

+——————+———+——-+—————————–+—————————–+————+

→ 目的是告诉你，这个集群应该有哪些master节点，记录ID信息，方便成员添加删减（member remove/add）

步骤 2： 移除故障的Etcd 成员

将上一步查到的 etcd1 的ID 填入下方（例如：1203cdd3ad75e761）。

/usr/local/bin/etcdctl \

–cacert=/etc/etcd/ssl/ca.pem \

–cert=/etc/etcd/ssl/etcd.pem \

–key=/etc/etcd/ssl/etcd-key.pem \

–endpoints=https://192.168.40.181:2379,https://192.168.40.182:2379 \

member remove [故障节点ID]

步骤 3： 移除故障的 Etcd 成员

kubectl delete node zwymaster1

（如果没装kubelet是找不到的）

阶段二：故障节点清理与证书同步(Master1 执行)

步骤 1： 停止所有相关服务并清理数据

**警告：**必须删除Etcd 数据目录，否则会产生Cluster ID 不匹配错误。

systemctl stop etcd kube-apiserver kube-controller-manager kube-scheduler

# mv数据目录

mv /var/lib/etcd/default.etcd /var/lib/etcd/default.etcd_bak

步骤 2： 重建目录并同步证书(从Master2 拷贝)

# master1上进行

mv /etc/etcd/ssl /etc/etcd/ssl_bak

mv /etc/kubernetes/ssl /etc/kubernetes/ssl_bak

mkdir -p /etc/etcd/ssl /etc/kubernetes/ssl

# 在 Master2 执行分发（假设有免密登录）

scp /etc/etcd/ssl/*.pem zwymaster1:/etc/etcd/ssl/

# 同时确保 K8s 组件证书也同步过去

# scp /etc/kubernetes/ssl/*.pem zwymaster1:/etc/kubernetes/ssl/

阶段三：Etcd 集群重新加入

步骤 1：在存活节点预添加成员：

→ 告知集群：准备接纳一个名为 etcd1 的新成员，其通讯地址为192.168.40.180。

(为啥是2380 啊端口？？) → 2379是对外，2380是对内的

/usr/local/bin/etcdctl \

–cacert=/etc/etcd/ssl/ca.pem \

–cert=/etc/etcd/ssl/etcd.pem \

–key=/etc/etcd/ssl/etcd-key.pem \

–endpoints=https://192.168.40.181:2379 \

member add etcd1 –peer-urls=https://192.168.40.180:2380

ETCD_NAME=”etcd1”

ETCD_INITIAL_CLUSTER=”etcd3=https://192.168.40.182:2380,etcd2=https://192.168.40.181:2380,etcd1=https://192.168.40.180:2380“

ETCD_INITIAL_ADVERTISE_PEER_URLS=”https://192.168.40.180:2380“

ETCD_INITIAL_CLUSTER_STATE=”existing” → 加入一个已经存在的集群

步骤 2：修改Master1 的Etcd 配置文件(Master1 执行)

修改 /etc/etcd/etcd.conf ，关键点是将状态从 new 改为 existing 。

# 修改 ETCD_INITIAL_CLUSTER_STATE 这一行

sed -i ‘s/ETCD_INITIAL_CLUSTER_STATE=”new”/ETCD_INITIAL_CLUSTER_STATE=”existing”/g’ /etc/etcd/etcd.conf

步骤 3：启动 Master1 的 Etcd

systemctl daemon-reload

systemctl enable etcd –now

阶段四：恢复K8s 控制平面(Master1 执行)

Etcd 正常后，K8s 组件即可连接Etcd 恢复工作。

步骤 1：启动 K8s 各个组件服务

systemctl start kube-apiserver

systemctl start kube-controller-manager

systemctl start kube-scheduler

# 设置开机自启

systemctl enable kube-apiserver kube-controller-manager kube-scheduler

阶段五：集群健康检查(Master1 执行)

步骤 1：验证Etcd 集群健康度

/usr/local/bin/etcdctl –write-out=table \

–cacert=/etc/etcd/ssl/ca.pem \

–cert=/etc/etcd/ssl/etcd.pem \

–key=/etc/etcd/ssl/etcd-key.pem \

–endpoints=https://192.168.40.180:2379,https://192.168.40.181:2379,https://192.168.40.182:2379 \

endpoint status –cluster

+—————————–+——————+———+———+———–+————+———–+————+——————–+——–+

| ENDPOINT | ID | VERSION | DB SIZE | IS LEADER | IS LEARNER | RAFT TERM | RAFT INDEX | RAFT APPLIED INDEX | ERRORS |

+—————————–+——————+———+———+———–+————+———–+————+——————–+——–+

| https://192.168.40.182:2379 | 18e1ac83234cec44 | 3.4.13 | 5.8 MB | false | false | 1133 | 333891 | 333891 | |

| https://192.168.40.181:2379 | 213823ebf4891b65 | 3.4.13 | 5.9 MB | true | false | 1133 | 333891 | 333891 | |

| https://192.168.40.180:2379 | 96e71846171e5ac5 | 3.4.13 | 5.9 MB | false | false | 1133 | 333891 | 333891 | |

+—————————–+——————+———+———+———–+————+———–+————+——————–+——–+

判断健不健康的标准：

1、ERRORS 为空

2、有且只有 1 个 IS LEADER = true

3、三个节点的 RAFT INDEX 完全一致 = 数据同步

步骤 2：验证K8s 节点状态

kubectl get nodes

kubectl get cs ComponentStatus（组件状态）

[root@zwymaster1 ~]# kubectl get cs
