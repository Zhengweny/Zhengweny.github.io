K8s 控制器 ReplicaSet

发表于2026-05-07|更新于2026-05-08|学习类云原生控制器

1. 核心定位：为何需要 ReplicaSet

+—————————————————————————————————————————————————————-+
| 解决自主式 Pod 无法自愈的问题：自主 Pod 被删除后无法恢复，线上风险高；ReplicaSet 作为 Pod 控制器，能监测 Pod 状态，实现故障自动恢复、副本数量 “多退少补”。 |
| |
| 注意：生产环境不直接用 ReplicaSet，优先用更高级的 Deployment（Deployment 管理 ReplicaSet，支持声明式更新和历史变更回溯）。 |
+—————————————————————————————————————————————————————-+

2. 核心原理：Replicaset如何管理Pod？

3、Replicaset资源清单文件编写技巧

# 查看定义Replicaset资源需要的字段有哪些？

[root@xianchaomaster1 ~]# kubectl explain rs

KIND:     ReplicaSet

VERSION:  apps/v1

DESCRIPTION:

     ReplicaSet ensures that a specified number of pod replicas are running at

     any given time.

FIELDS:

   apiVersion <string>  #当前资源使用的api版本，跟VERSION:  apps/v1保持一致

   kind <string>     #资源类型，跟KIND: ReplicaSet保持一致

   metadata <Object> #元数据，定义Replicaset名字的

   spec <Object>     ##⭐定义副本数、定义标签选择器、定义Pod模板

   status <Object> #状态信息，不能改

# 查看replicaset的spec字段如何定义？

[root@xianchaomaster1 ~]# kubectl explain rs.spec

KIND:     ReplicaSet

VERSION:  apps/v1

RESOURCE: spec <Object>

DESCRIPTION:

     Spec defines the specification of the desired behavior of the ReplicaSet.

     More info:

     https://git.k8s.io/community/contributors/devel/sig-architecture/api-conventions.md#spec-and-status

     ReplicaSetSpec is the specification of a ReplicaSet.

FIELDS:

   minReadySeconds  <integer> # 要求 Pod 在变为 Ready 后，必须持续保持 Ready 至少 N 秒，才会被计入“可用副本”；默认值: 0（即一旦 Ready 就计为可用）。

   replicas <integer>  #⭐ 定义的pod副本数，根据我们指定的值创建对应数量的pod

   selector <Object> -required-  #⭐ 用于匹配pod的标签选择器

   template <Object>      # ⭐定义Pod的模板，基于这个模板定义的所有pod是一样的

# 查看replicaset的spec.template字段如何定义？

# ⭐对于template而言，其内部定义的就是pod，pod模板是一个独立的对象，字段与先前的pod也一致

[root@xianchaomaster1 ~]# kubectl explain rs.spec.template

KIND:     ReplicaSet

VERSION:  apps/v1

RESOURCE: template <Object>

DESCRIPTION:

     Template is the object that describes the pod that will be created if

     insufficient replicas are detected。PodTemplateSpec describes the data a pod should have when created from a

     template

FIELDS:

   metadata <Object> # ⭐ 在Template下，这个字段通常放labels即可，不需要写name字段，因为没有意义，因为 Pod 名称由控制器自动生成的，<控制器名>-<hash>-<随机串>

   spec <Object>

4、Replicaset管理pod：扩容、缩容、更新

1) 动态扩容（增加 Pod 副本）：（scale out）

# 修改 ReplicaSet 配置文件（如 replicaset.yaml）中 replicas 的值

（例如从 3 改为 4）

kubectl apply -f replicaset.yaml

# 查看 RS 状态，DESIRED、CURRENT、READY 均会同步为目标值：

kubectl get rs

# 示例输出：frontend 4 4 4 62m

# 查看 Pod，新增 Pod 会自动创建：

kubectl get pods

# 新增 Pod（如 frontend-kzjm7）状态为 Running

2) 动态缩容（减少 Pod 副本）（scale in）

# 修改配置文件中 replicas 的值（例如从 4 改为 2）。

kubectl apply -f replicaset.yaml

# 查看 RS 状态，副本数会自动减少至目标值：

kubectl get rs

# 示例输出：frontend 2 2 2 70m

3) Pod 更新（更换镜像）

⭐[ReplicaSet 本身不支持自动滚动更新，需手动干预旧 Pod 以触发新配置生效。]{.mark}

👉现象：

仅修改 `template.spec.containers[*].image` 并 `kubectl apply` 后，ReplicaSet 不会主动替换已有 Pod；删除旧Pod之后，新建的Pod才会使用新镜像。

👉若需让新镜像生效，有三种方式：

1) 手动逐个删除旧 Pod，ReplicaSet 会按新模板重建（人工“滚更”，有操作风险）。

2) 使用 Deployment（推荐生产）：原生支持滚动更新、回滚、暂停/恢复等发布能力。

3) 蓝绿发布：保留旧 RS（rs1），新建新 RS（rs2）使用新镜像，切换 Service 的 selector 到 rs2，验证无误后下线 rs1。

5、本章重点

- 重点1：ReplicaSet 的强项是“维持副本数”（字段：spec.replicas），不是“发布管理”。更新模板不会替换存量 Pod。

- 重点2：生产应使用 Deployment 的滚动更新或蓝绿发布；ReplicaSet 更适合作为底层副本控制器或教学演示。
