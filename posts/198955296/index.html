1、docker配额

1.1 docker运行容器控制CPU使用

1.1.1  Docker运行容器CPU份额配置指南

1、设置cpu参数配额：

-c 1024 (可指定为512/2048….根据你需要的权重进行设置)

参数说明：

参数： -c, –cpu-shares num

说明： 设置容器的 CPU 份额值 (相对权重)

重要说明：

1、cpu-shares 参数用于指定CPU 份额值

2、是一个弹性加权值，不是说你定义了1024（1核），它就只有1核（比如单容器独占服务器时，就是没有其它容器竞争的情况下，是可能超过1G的）

⭐3、默认份额值是1024。份额越大说明cpu的时间越多。说明容器性能更好

4、同一个cpu核心上同时运行多个容器，CPU的加权值效果才会显现出来

案例分析：

假设有两个容器A和B，CPU 份额分别为 2048 和 1024

情况一：A 和 B 正常运行

如果容器 A 和 B 占用同一个 CPU，当 CPU 进行时间片分配时，容器 A 比容器 B 多一倍的机会获得 CPU 时间片。

⭐在同一个cpu上，份额大的占用的cpu更多，性能更好

情况二：取决于其他容器的运行状态

1）容器 A 的进程一直处于空闲状态，那么容器 B 可以获取比容器 A 更多的 CPU 时间片。

⭐有一个处于空闲状态时，另一个运行的容器会获得更大的份额

⭐2）如果主机上只运行了一个容器，即使它的CPU份额只有50，同样也可以独占整个主机的CPU资源

**总结：**配置cpu份额的分配其实在多个容器争抢同一个cpu资源时，CPU配额才会生效。

** 1.1.2 Docker运行容器跑在指定的cpu上**

Docker 允许通过 –cpuset 参数将容器绑定到特定的 CPU 和内存节点上。对于多核 CPU 服务器，这些参数有用，可以控制容器运行时限定使用哪些 CPU 和内存节点。具体参数如下：

–cpuset-cpus：指定容器可以使用的具体CPU是哪个 。

–cpuset-mems：指定容器可以使用的内存节点。（用于多内存场景的指定，即以下的NUMA拓扑架构）

# 备注

⭐NUMA 拓扑结构（小型机）：多 CPU、多内存节点的服务器，使用以上参数可以对容器进行优化。如果服务器只有一个内存节点，则 –cpuset-mems 的配置不会有明显效果。

（我们日常用那些x86架构的服务器，大多是多cpu配一个固定内存，没有多内存节点的情况）

⭐服务器架构概述（了解一下）：

· SMP：多处理器共享同一内存，适用于中小规模并行处理。

· NUMA：多个节点，每个节点有独立的内存和 CPU，适用于需要高吞吐量的应用。

· MPP：大量独立节点并行处理，适用于高性能计算和大数据处理。

** 1.1.3 CPU配额控制参数的混合使用（案例）**

案例：

创建两个容器实例: docker10 和docker20。 让docker10和docker20只运行在cpu0和cpu1上，docker10给设置512份额，docker20给设置1024份额，最终测试一下docker10和docker20使用cpu的百分比。实验拓扑图如下：

1、分别设置两个容器

2、压降测试，安装stress命令

3、对比是否docker20比docker10的cpu时间分配多一倍

注意：cpu必须是4核及以上，否则cpu0和1跑慢了，服务器就没有预留cpu了，会挂。

运行两个容器：

# 指定docker10只能在cpu0和cpu1上运行，而且docker10的使用cpu的份额512

docker run -itd –name docker10 –cpuset-cpus 0,1 –cpu-shares 512 rockylinux:8.9 /bin/bash

# 指定docker20只能在cpu0和cpu1上运行，而且docker20的使用cpu的份额1024，比dcker10多一倍

docker run -itd –name docker20 –cpuset-cpus 0,1 –cpu-shares 1024 rockylinux:8.9 /bin/bash

压降测试：

# 安装stress命令

yum install -y stress

# 备注stress用法：

命令：stress -c 2 -i 2 –verbose –timeout 60s  

表示：

-c → 2个cpu

-i → 2个io进程

–verbose → 查看压测信息

–timeout 20s → 20秒后停止运行

# 将stress 命令传输到docker10和docker20

[root@localhost ~]# docker cp /usr/bin/stress docker10:/usr/bin/

[root@localhost ~]# docker cp /usr/bin/stress docker20:/usr/bin/

# 打开3个窗口进行模拟

窗口1：让docker10跑满2个cpu，产生2个IO进程，–verbose看压测信息，60s后停止

[root@d9c9e9e56b2e /]# stress -c 2 -i 2 –verbose –timeout 60s

窗口2：同理让docker20去跑

[root@d90d1bb2df80 /]# stress -c 2 -i 2 –verbose –timeout 60s

窗口3：top比对两者的信息

如下图，docker20比docker10所占用的cpu份额会是docker10的两倍

⭐ 应用场景

–cpuset-cpus： 指定在哪些cpu上运行，目的是为了留出CPU，防止容器被黑或者跑满时，导致整个服务器不可用

–cpu-shares：指定份额，一般默认是1034，但对于mysql数据库性能要求比较高时，在创建mysql容器时，我们会指定成功2048，也就是默认的2，此时mysql这个容器性能就会比其它容器高些

1.2 docker运行容器控制内存使用

Docker提供参数-m, –memory=””限制容器的内存使用量。

例1：允许容器使用的内存上限为128M（最多用128M）：

[root@localhost ~]# docker run -it -m 128m rockylinux:8.9

容器内查看内存：

[root@0c0b13cfadca /]# cat /sys/fs/cgroup/memory/memory.limit_in_bytes

134217728

例2：创建一个docker，只使用2个cpu核心，只能使用128M内存

[root@localhost ~]# docker run -it –cpuset-cpus 0,1 -m 128m rockylinux:8.9

1.3 ⭐docker运行容器确保容器在关机时可以自动起来

# ⭐ 就是run启动容器时，加入–restart=always这个参数， 在容器关机时会自动起来，类似于开机自启动

[root@localhost ~]# docker run –name always -itd –restart=always rockylinux:8.9

# 测试关机启动

reboot -f

#服务器启动之后，可以看到always这个容器还是正常运行的

[root@localhost ~]# docker ps

CONTAINER ID IMAGE COMMAND CREATED STATUS PORTS NAMES

2a4e19794477 rockylinux:8.9 “/bin/bash” 2 minutes ago Up About a minute always
