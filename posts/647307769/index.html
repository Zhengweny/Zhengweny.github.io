Storageclass存储类动态生成存储

发表于2026-05-07|更新于2026-05-08|学习类云原生存储
|总字数:1.7k|阅读时长:7分钟|浏览量:

一、为什么需要 StorageClass

+——————————————————————————————————————————————————————————+
| [PV（持久卷）和 PVC（持久卷声明）是静态绑定，得先手动创建好 PV，PVC 再和 PV 一对一绑定。如果有上千个 PVC 需求，就要手动创建上千个 PV，运维成本极高。]{.mark} |
| |
| StorageClass核心作用：[自动创建 PV 的模板]{.mark}[，实现 PV 的动态供给 —— 你提交 PVC 后，K8s 会根据 StorageClass 的配置自动创建对应的 PV，不用手动管 PV 了。]{.mark} |
+——————————————————————————————————————————————————————————+

二、StorageClass 核心字段

[通过]{.mark}kubectl explain storageclass[能看到关键字段，核心字段解释如下：]{.mark}

字段 解释

[provisioner（提供者）]{.mark} [存储供应商（比如 NFS、Ceph），指定用哪种存储插件创建 PV**（必填项）**]{.mark}

[reclaimPolicy]{.mark} [PV 的回收策略（比如 Delete 删除、Retain 保留）]{.mark}

[allowVolumeExpansion]{.mark} 是否允许 PVC 扩容（只能放大，不能缩小）

[parameters]{.mark} 存储的自定义参数（比如 NFS 的服务器地址、路径）

[metadata.name]{.mark} [StorageClass 的名称（PVC 要通过这个名称关联）（必填项）]{.mark}

三、实战：基于 NFS 实现 StorageClass 动态供给 PV

前置说明

[要让 StorageClass 支持 NFS，需要先装]{.mark}nfs-subdir-external-provisioner[（NFS 供应者）]{.mark}[—— 这个程序是连接 K8s 和 NFS 服务器的桥梁，负责自动创建 NFS 类型的 PV]{.mark}

步骤 1：准备 NFS Provisioner 镜像

[把镜像包]{.mark}nfs-subdir-external-provisioner.tar.gz[传到节点]{.mark}xianchaonode1[和]{.mark}xianchaonode2[，导入镜像：]{.mark}

[root@node1 ~]# ctr -n=k8s.io images import nfs-subdir-external-provisioner.tar.gz

[root@node2 ~]# ctr -n=k8s.io images import nfs-subdir-external-provisioner.tar.gz

步骤 2：创建 ServiceAccount（SA）并授权

2.1 什么是 SA

[SA（ServiceAccount：“服务账号”）是给 Pod 用的 “账号”，Pod 通过 SA 获取 K8s API 的操作权限，这里给 NFS Provisioner 的 Pod 授权，让它能创建 / 删除 PV。]{.mark}

2.2 创建 SA 配置文件

# 可简写为sa

[root@master1 StorgeClass]# kubectl explain sa

KIND: ServiceAccount

VERSION: v1

# 创建SA配置文件

[root@master1 StorgeClass]# cat serviceaccount.yaml

apiVersion: v1

kind: ServiceAccount

metadata:

name: nfs-provisioner

# 执行创建

[root@master1 StorgeClass]# kubectl apply -f serviceaccount.yaml

[root@master1 StorgeClass]# kubectl get sa # nfs-provisioner账号已创建

NAME SECRETS AGE

default 0 114d

nfs-provisioner 0 2m58s

2.3 给 SA 授权（集群管理员权限）

# 小白注释：创建集群角色绑定，把cluster-admin（最高权限）绑定到default命名空间的nfs-provisioner SA

# 模板

kubectl create clusterrolebinding 【绑定名称，自定义一个名字】 –clusterrole=【集群角色名】 –serviceaccount=【命名空间】:【服务账号名】

# 给SA授权

[root@xianchaomaster1]# kubectl create clusterrolebinding nfs-provisioner-test –clusterrole=cluster-admin –serviceaccount=default:nfs-provisioner

# 查看创建结果（新版k8s可以直接 get crb，旧版只能写全程clusterrolebinding）

[root@master1 StorgeClass]# kubectl get clusterrolebinding nfs-provisioner-test

NAME ROLE AGE

nfs-provisioner-test ClusterRole/cluster-admin 3m32s

步骤 3：配置 NFS 服务器共享目录

3.1 创建共享目录

[root@master1 ~]# mkdir /data/nfs_pro -p

3.2 配置 NFS 共享规则

vi /etc/exports

/data/nfs_pro 192.168.40.0/24(rw,no_root_squash)

# 注释：

# /data/nfs_pro：要共享的目录

# 192.168.40.0/24：允许访问的网段

# rw：读写权限；no_root_squash：客户端用root访问时，保留root权限

3.3 生效 NFS 配置

[root@xianchaomaster1 ~]# exportfs -arv

# 注释

# a=全部导出，r=重新读取配置，v=显示详细信息

步骤 4：部署 NFS Provisioner（这个就是PV存储的动态提供者）

[创建]{.mark}nfs-deployment.yaml[配置文件]{.mark}

kind: Deployment

apiVersion: apps/v1

metadata:

name: nfs-provisioner # Deployment名称

spec:

selector:

matchLabels:

app: nfs-provisioner # 匹配Pod的标签

replicas: 1 # 只启动1个副本

strategy:

type: Recreate # 重建策略（更新时先删旧Pod再建新的）

template:

metadata:

labels:

app: nfs-provisioner # Pod的标签，和selector匹配

spec:

serviceAccount: nfs-provisioner # 引用上面创建的SA

containers:

  • name: nfs-provisioner # 容器名称

image: registry.cn-beijing.aliyuncs.com/mydlq/nfs-subdir-external-provisioner:v4.0.0 # 镜像地址

imagePullPolicy: IfNotPresent # 优先用本地镜像，没有再拉取

volumeMounts:

  • name: nfs-client-root # 卷名称，和下面volumes对应

mountPath: /persistentvolumes # 容器内挂载路径（Provisioner工作目录）

env:

  • name: PROVISIONER_NAME

value: example.com/nfs # ⭐供应者名称（关键！后面StorageClass要和这个一致）

  • name: NFS_SERVER

value: 192.168.40.180 # NFS服务器IP（改成你的NFS服务器地址）

  • name: NFS_PATH

value: /data/nfs_pro # NFS共享目录（和步骤3的目录一致）

volumes:

  • name: nfs-client-root # 卷名称，和volumeMounts对应

nfs:

server: 192.168.40.180 # NFS服务器IP

path: /data/nfs_pro # NFS共享目录

执行部署

[root@master1 ~]# kubectl apply -f nfs-deployment.yaml

deployment.apps/nfs-provisioner created

[root@master1 ~]#

[root@master1 ~]# kubectl get pods | grep nfs

nfs-provisioner-6fff756f74-48nvl 1/1 Running 0 18s

步骤 5：创建 StorageClass

⭐注意：StorageClass，单词分别第一个字母要大写

[root@master1 ~]# kubectl explain StorageClass

[root@master1 ~]# cat nfs-storgeclass.yaml

kind: StorageClass

apiVersion: storage.k8s.io/v1

metadata:

name: nfs

provisioner: example.com/nfs

执行创建

[root@master1 ~]# kubectl apply -f nfs-storgeclass.yaml

storageclass.storage.k8s.io/nfs created

[root@master1 ~]# kubectl get StorageClass

NAME PROVISIONER RECLAIMPOLICY VOLUMEBINDINGMODE ALLOWVOLUMEEXPANSION AGE

nfs example.com/nfs Delete Immediate false 34s

# 注释

Delete是默认回收策略，Immediate是立即绑定， ALLOWVOLUMEEXPANSION为false是不给扩容

步骤 6：创建 PVC（自动生成 PV）

创建claim.yaml

[root@master1 StorgeClass]# cat claim.yaml

apiVersion: v1

kind: PersistentVolumeClaim

metadata:

name: test-claim1

spec:

accessModes:

  • ReadWriteOnce #⭐ 访问模式类型explain无法直接看到，背下来吧，ReadWriteOnce (RWO)、ReadOnlyMany (ROX)、ReadWriteMany (RWX)

resources:

requests:

storage: 1Gi # ⭐ spec.resource.request.storage中的容量storage单词背下来，explain无法直接看到

storageClassName: nfs # ⭐ 一定要关联StorageClass的名字（需一致）

[执行创建：]{.mark}

[root@master1 StorgeClass]# kubectl apply -f claim.yaml

persistentvolumeclaim/test-claim1 created

# 检查PVC和自动生成的PV

[root@master1 StorgeClass]# kubectl get pvc

NAME STATUS VOLUME CAPACITY ACCESS MODES STORAGECLASS VOLUMEATTRIBUTESCLASS AGE

test-claim1 Bound pvc-f1e6c83d-65e2-4f1b-a3f1-4e5e2722cb5a 1Gi RWO nfs <unset> 8m40s

# 注释：

# STATUS是Bound，说明PVC和自动生成的PV绑定成功

# pvc-f1e6c83d-65e2-4f1b-a3f1-4e5e2722cb5a即为PV，无需手动创建

步骤 7：创建 Pod 挂载 PVC

[root@master1 StorgeClass]# cat read-pod.yaml

apiVersion: v1

kind: Pod

metadata:

name: read-pod

spec:

containers:

  • name: read-pod

image: nginx

imagePullPolicy: IfNotPresent

volumeMounts:

  • mountPath: /usr/share/nginx/html

name: nfs-pvc # 有点类似于，容器内的数据要映射到外面的意思，因此存储路径要和外部的一致（volume.name）

restartPolicy: “Never” # pod退出后不重启

volumes:

  • name: nfs-pvc # 外部的存储卷，和volumeMounts对应

persistentVolumeClaim: # 引用PVC来获取存储资源

claimName: test-claim1 # 这里就是上面创建的pvc的名字

执行创建

[root@master1 StorgeClass]# kubectl apply -f read-pod.yaml

pod/read-pod created

[root@master1 StorgeClass]# kubectl get pods | grep read

read-pod 1/1 Running 0 6m19s

四、⭐⭐核心步骤总结

+———————————————————————————–+
| 装供应者：部署 NFS Provisioner（给 K8s 提供创建 NFS PV 的能力），并配置 SA 授权； |
| |
| 建模板：创建 StorageClass，指定 Provisioner 名称（和 Provisioner 配置一致）； |
| |
| 提需求：创建 PVC，指定 StorageClass 名称，K8s 自动生成 PV 并绑定； |
| |
| 用存储：创建 Pod，挂载 PVC 即可使用动态生成的 NFS 存储。 |
+———————————————————————————–+
