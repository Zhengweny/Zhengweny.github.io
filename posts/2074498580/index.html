Docker数据持久化及网络模式介绍

发表于2026-05-07|更新于2026-05-08|学习类云原生Docker
|总字数:2k|阅读时长:9分钟|浏览量:

1、⭐Docker持久化的目的及方式

目的：防数据丢失

方式：

1）Bind Mounts：将宿主机上的特定目录挂载到容器内（一般是测试用：直接-v挂载）

⭐ -v 本地路径：容器路径

例如：运行一个名为mynginx1的容器，并进行持久化

docker run -d -p 80 –name mynginx1 -v /root/mynginx/html（本地目录）:/usr/share/nginx/html（容器目录） nginx:1.26（镜像名）

2）Volumes：由Docker管理的特殊目录，用于存储数据（正式环境一般都用这个）

# 创建Volume:

docker volume create myvolume(volume名随机取)

# 同样是-v挂载，但是只需要定义volume名（-v 本地卷名：容器内的目录）

-v myvolume(卷名):/usr/share/nginx/html（容器内的目录）

例如：

docker run -d -p 81:80 –name mynginx2 -v myvolume:/usr/share/nginx/html nginx:1.26

# 查看volume目录及数据

docker volume inspect myvolume (卷名)

1.1 [使用Bind Mounts实现数据持久化]{.mark}

其实就是利用命令，用 **“ -v 本地路径：容器路径“**来完成数据持久化

案例：使用 Bind Mounts

假设我们要运行一个简单的 Nginx 容器，并将宿主机上的 html 目录挂载到容器内的 /usr/share/nginx/html 目录。

1）创建一个目录：

[root@localhost ~]# mkdir -p /root/mynginx/html

2）在目录中创建一个简单的HTML文件：

[root@localhost ~]# echo “Hello, My name is Jane” > /root/mynginx/html/index.html

3）运行nginx容器并使用Bind Mounts

# 记载镜像

[root@localhost mynginx]# docker load -i nginx1.26.tar.gz

# 运行容器

[root@localhost mynginx]# docker run -d -p 80 –name mynginx1 -v /root/mynginx/html:/usr/share/nginx/html nginx:1.26

# 测试是否有结果输出

[root@localhost mynginx]# docker ps

CONTAINER ID IMAGE COMMAND CREATED STATUS PORTS NAMES

3d63d36a9be3 nginx:1.26 “/docker-entrypoint.…” 9 seconds ago Up 8 seconds 0.0.0.0:32770->80/tcp, :::32770->80/tcp mynginx1

[root@localhost mynginx]# curl 192.168.40.180:32770

Hello, My name is Jane

1.2 [使用Volume实现数据持久化（比较正式的用法）]{.mark}

# 创建一个volume

[root@localhost mynginx]# docker volume create myvolume

# 运行容器并使用volume

[root@localhost mynginx]# docker run -d -p 81:80 –name mynginx2 -v myvolume:/usr/share/nginx/html nginx:1.26

# 查看volume的目录及数据

[root@localhost mynginx]# docker volume inspect myvolume

[

{

“CreatedAt”: “2025-07-26T20:13:00+08:00”,

“Driver”: “local”,

“Labels”: null,

“Mountpoint”: “/var/lib/docker/volumes/myvolume/_data”, # 这个是Dokcer默认为volume创建的数据目录

“Name”: “myvolume”,

“Options”: null,

“Scope”: “local”

}

]

# myvolume的数据目录和容器内的是保持一致的

myvolume数据目录：

[root@localhost _data]# ll /var/lib/docker/volumes/myvolume/_data

total 8

-rw-r–r– 1 root root 497 May 28 2024 50x.html

-rw-r–r– 1 root root 615 May 28 2024 index.html

容器内目录：

root@74a681682d4f:/# ls -l /usr/share/nginx/html/

total 8

-rw-r–r– 1 root root 497 May 28 2024 50x.html

-rw-r–r– 1 root root 615 May 28 2024 index.html

⭐ # 此时在本地模拟修改数据

[root@localhost _data]# echo “Hello, My name is Jane” > index.html

重新访问，说明容器已同步修改

[root@localhost _data]# curl 192.168.40.180:81

Hello, My name is Jane

⭐2、docker容器的网络模式

2.1 none 模式 （只有lo网卡）

# 创建容器时没有任何网络地址，只有lo网卡也就是自己127.0.0.1

# 在镜像centos上指定运行一个网络模式为none（–net=none），容器名为none(–name none)的容器

[root@localhost _data]# docker run -itd –name none –net=none centos

# 进入查看

[root@localhost _data]# docker exec -it none /bin/bash

# 只有lo回环网卡

[root@1186a10a849b /]# ip a

1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000

link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00

inet 127.0.0.1/8 scope host lo

valid_lft forever preferred_lft forever

2.2 container 模式（将不同容器的俩IP设置一样）

# 刚刚2.1已经创建一个lo，即只有127.0.0.1i地址的容器了，此时我要创建一个与none容器ip一致的容器，就属于container模式

⭐ –net-container:指定的容器名 → 新创建的容器将和指定容器的网络保持一致

#新创建的con容器和已有的none容器ip地址保持一致

[root@localhost _data]# docker run -itd –name con –net=container:none centos

# 检查，确实新容器con和之前的none保持一致

[root@localhost _data]# docker exec -it con /bin/bash

[root@1186a10a849b /]# ip a

1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000

link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00

inet 127.0.0.1/8 scope host lo

valid_lft forever preferred_lft forever

2.3 bridge 桥接模式（docker的默认模式：通过网桥docker0的网段划分IP分配）

⭐ # 本地网桥是172.17.0.1/16，也就是根据这个网段随机分配给容器地址。通过NAT（网络地址转换）与宿主机的网络进行通信

[root@localhost _data]# ip a

…

inet 172.17.0.1/16 brd 172.17.255.255 scope global docker0

…..

# 默认是bridge桥接模式，不指定也是可以的

[root@localhost _data]# docker run -itd –name bridge centos

# 查看IP地址，能看到分配了172.17.0.6这个IP给中国容器

[root@localhost _data]# docker exec -it bridge /bin/bash

2.4 host模式 （容器和宿主机的IP保持一致）

注意：这种性能会更好，但是容器发生端口冲突，也比较少用

[root@localhost _data]# docker run -itd –name host –net=host centos

# 查看IP，发现所有IP，包括docker的全部都是和宿主机一致的网络
