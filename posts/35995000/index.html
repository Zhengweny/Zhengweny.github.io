系统要求

操作系统：CentOS 7.9 或 RockyLinux 8.9（实验用的是这个）

配置：4GB内存 / 4vCPU / 60GB硬盘

网络：NAT模式（优先），桥接模式（备选）

基础环境准备（三台设备都要准备）

安装基础软件包

yum install -y device-mapper-persistent-data lvm2 wget net-tools nfs-utils \

lrzsz gcc gcc-c++ make cmake libxml2-devel openssl-devel curl curl-devel \

unzip sudo ntp libaio-devel wget vim ncurses-devel autoconf automake \

zlib-devel python-devel epel-release openssh-server socat ipvsadm \

conntrack telnet ipvsadm

配置静态IP

vim /etc/sysconfig/network-scripts/ifcfg-ens160

TYPE=Ethernet

PROXY_METHOD=none

BROWSER_ONLY=no

BOOTPROTO=static

IPADDR=192.168.40.180 # 根据节点修改

NETMASK=255.255.255.0

GATEWAY=192.168.40.2

DNS1=192.168.40.2

DEFROUTE=yes

IPV4_FAILURE_FATAL=no

IPV6INIT=yes

IPV6_AUTOCONF=yes

IPV6_DEFROUTE=yes

IPV6_FAILURE_FATAL=no

IPV6_ADDR_GEN_MODE=eui64

NAME=ens160

DEVICE=ens160

ONBOOT=yes

centos重启网络

service network restart

rockylinux重启网络

#重载网卡配置

#开启网卡

# 重启后验证

getenforce # 应显示Disabled

⭐配置内核参数（数据包转发功能）

modprobe br_netfilter

备注：（这是Kubernetes网络策略正常工作的前提）

modprobe → Linux内核模块：加载工具

br_netfilter → Linux内核模块：在网桥接口上启用iptables规则

vim /etc/sysctl.d/k8s.conf

net.bridge.bridge-nf-call-ip6tables = 1

net.bridge.bridge-nf-call-iptables = 1

net.ipv4.ip_forward = 1

⭐备注：

net.bridge.bridge-nf-call-ip6tables = 1 #允许处理IPv6的iptables规则及数据包

net.bridge.bridge-nf-call-iptables = 1 #允许处理IPv4的iptables规则及数据包

net.ipv4.ip_forward = 1 # 启用IPv4数据包转发功能，允许系统作为路由器转发数据包，Pod之间通信需要此功能

# 启用

sysctl -p /etc/sysctl.d/k8s.conf

⭐关键配置参数说明：

1）InitConfiguration部分[初始化配置]：

advertiseAddress：API Server对外通告的IP地址

criSocket：容器运行时接口地址

imagePullPolicy：镜像拉取策略

taints：节点污点配置（null表示无污点）

2）ClusterConfiguration部分[集群配置]：

certificatesDir：TLS证书存储目录

clusterName：集群名称

etcd.dataDir：etcd数据存储目录

imageRepository：镜像仓库地址（使用国内镜像加速）

kubernetesVersion：Kubernetes版本

networking：网络配置

dnsDomain：集群DNS域名

podSubnet：Pod网段

serviceSubnet：Service网段

网络插件安装

1、安装Calico网络插件

# 导入Calico镜像，所有节点都执行

ctr -n=k8s.io images import calico.tar.gz

# 应用Calico配置，仅在master上执行

kubectl apply -f calico.yaml

⭐注意：需要修改calico.yaml中的网卡配置

- name: IP_AUTODETECTION_METHOD

value: “interface=ens33” # 根据实际网卡名修改

⭐网络插件一些对比分析

Flannel：是一个轻量级的 CNI 插件，一般只能提供IP，无法做网络隔离

Calico：是一个完全基于BGP协议（核心路由协议）的CNI插件，不止可以做IP分配，还可以做网络隔离

Weave Net：隧道由UDP封装，仅支持进出网络策略

Cilium：：比较新的技术，市场有在用，一个支持L3、L4和L7网络安全的CNI插件，具有网络和安全功能集成，使用eBPF技术，可以实现更好的性能和可观测性。

⭐为什么k8s需要网络插件

Kubernetes本身不提供网络功能

需要CNI（Container Network Interface）插件实现Pod间通信

网络插件负责IP地址分配、路由配置、网络策略等
