基于docker做容器从harbor拉取镜像（测试k8s）

发表于2026-05-07|更新于2026-05-08|学习类云原生Harbor
|总字数:873|阅读时长:3分钟|浏览量:

一、整体目标

让 K8s 集群所有节点能从私有 Harbor 镜像仓库（192.168.40.62）拉取镜像并创建 Pod

二、操作

1. 配置 Docker（所有 K8s 节点执行）

[作用]{.mark}：给 Docker 配镜像加速源、信任私有 Harbor 仓库、统一 cgroup 驱动（K8s 要求）。

# 覆盖写入Docker核心配置文件daemon.json（不存在则创建）

cat> /etc/docker/daemon.json <<EOF

{

“registry-mirrors”: [ # 镜像加速源（拉取公网镜像更快）

“https://p15n4xfi.mirror.aliyuncs.com“, #这里已经用了自己的阿里云加速器

“https://registry.docker-cn.com“,

“https://docker.mirrors.ustc.edu.cn“,

“https://dockerhub.azk8s.cn“,

“http://hub-mirror.c.163.com“

],

“insecure-registries”: [ # 信任的非HTTPS私有仓库（小白重点：Harbor默认HTTP需加这个）

“192.168.40.62”, # Harbor服务器IP

“harbor” # Harbor主机名（配合hosts解析）

],

“exec-opts”: [“native.cgroupdriver=systemd”] # K8s要求的cgroup驱动（⭐和K8s统一，避免兼容问题，用docker的时候强烈建议要添加上；用containerd大概率不会出现兼容问题，所以可加可不加）

}

EOF

# 重启Docker让配置生效

systemctl restart docker

2. 修改 hosts 文件（所有 K8s 节点 + Harbor 机器执行）

[作用]{.mark}：让机器通过 “主机名” 直接访问对应 IP（不用记 IP，K8s 拉镜像时识别 harbor 主机名）。

[root@node1 ~]# cat /etc/hosts

127.0.0.1 localhost localhost.localdomain localhost4 localhost4.localdomain4

::1 localhost localhost.localdomain localhost6 localhost6.localdomain6

192.168.40.62 harborzhengwenyi.cn

192.168.40.180 master1

192.168.40.181 node1

192.168.40.182 node2

3. ⭐K8s 配置镜像拉取密钥 + 创建 Pod（仅 K8s 主节点执行）

[作用]{.mark}：K8s 拉私有 Harbor 镜像需要认证，先创建密钥，再用 Pod 引用密钥拉取镜像。

（1）⭐创建镜像拉取 Secret

# 创建Docker仓库认证密钥（注：把Harbor的账号密码存在K8s里）

kubectl create secret docker-registry registry-pull-secret \

–docker-server=192.168.40.62 \ # Harbor仓库地址

–docker-username=admin \ # Harbor默认管理员账号

–docker-password=Harbor12345 # Harbor默认密码

⭐注意：registry-pull-secret 这个是密钥名，后面创建pod拉取镜像时，要引用到这个名字

（2）创建 Pod（拉取 Harbor 镜像）

# 编写Pod配置文件pod.yaml

apiVersion: v1 # K8s API版本（固定写法）

kind: Pod # 资源类型（创建Pod）

metadata:

name: nginx # Pod名字（自定义）

namespace: default # 命名空间（默认即可）

spec:

imagePullSecrets: # ⭐引用上面创建的镜像拉取密钥（注：告诉K8s用这个密钥登录Harbor）

  • name: registry-pull-secret

containers:

  • name: nginx # 容器名字（自定义）

image: 192.168.40.62/library/nginx:v1.6 # 私有Harbor的镜像地址（IP/仓库名/镜像名:harbor中的版本）

imagePullPolicy: Always # 总是拉取镜像（小白：测试用，确保从Harbor拉最新的）

[执行创建并验证 Pod]{.mark}：

kubectl apply -f pod.yaml

# 查看Pod状态，Running则成功

kubectl get pod nginx

# 查看Pod日志/详情（排查失败原因）

kubectl describe pod nginx

三、核心总结

Docker 配置：核心是信任私有 Harbor（insecure-registries）+ 适配 K8s 的 cgroup 驱动，加速源是附加优化；

hosts 修改：解决 “主机名→IP” 解析，让 K8s/Harbor 互相识别；

K8s 操作：Secret 存 Harbor 账号密码，Pod 通过 imagePullSecrets 引用密钥，才能拉取私有镜像。

四、避坑点

Docker 配置后必须重启，否则不生效；

hosts 文件中 Harbor 的 IP 和主机名必须对应，否则解析失败；

Secret 的仓库地址、账号密码必须和 Harbor 一致，否则拉镜像认证失败；

Pod 的 image 地址要写全：HarborIP / 项目名 / 镜像名：版本（示例中 library 是 Harbor 默认项目）。
